# Контракт расчёта денежных потоков версии 1.0

`request.example.json` — действующий запрос для исходной сделки. `request.schema.json` и `response.schema.json` используют JSON Schema Draft 2020-12. Полный пример ответа — `outputs/sprint1_20261009/calculation.json`; отдельная копия тысяч строк не создаётся.

| Поле запроса | Тип и единицы | Смысл |
|---|---|---|
| schema_version | строка "1.0" | Версия контракта |
| deal.id | строка, 1–128 символов | Идентификатор сделки |
| deal.currency | "RUB" | Валюта платежей |
| deal.valuation_date | YYYY-MM-DD | Дата известного остатка и оценки PV |
| deal.outstanding_principal | строка с двумя знаками, >0 | Остаток основного долга в RUB |
| deal.annual_credit_rate | неотрицательная десятичная строка | Номинальная кредитная ставка в долях единицы |
| deal.first_payment_date | YYYY-MM-DD | Первая будущая выплата |
| deal.maturity_date | YYYY-MM-DD | Финальная дата погашения |
| deal.frequency_months | целое 1–120 | Шаг между платежами |
| deal.day_count | "ACT/365F" | Фактические дни / 365 |
| discounting.annual_rate | неотрицательная десятичная строка | Независимая дисконтная ставка |
| discounting.method | "PERIOD_SIMPLE_CHAIN" | DF_i = DF_(i−1)/(1+rate×days/365) |
| discounting.day_count | "ACT/365F" | База дисконтирования |
| payment_types | уникальный непустой список | ANN, SIMPLE, RGM |

Ответ содержит исходный request, methodology, results и sources. В каждом results[type]: summary и payments. Для платежа возвращаются номер, дата, дни, долг до/после, проценты, тело, платёж, ставки периода, DF и PV частей/всего платежа. Итоги содержат количество, номинальные суммы, PV, разницу с долгом и первый/последний платежи.

Деньги в запросе/платежах — строки с двумя знаками, без экспоненциальной записи. Ставки/DF ответа — 18 знаков после точки, PV — 8; внутренняя арифметика использует 40 значащих цифр. Это формат сериализации, а не промежуточное округление. При чрезвычайно высоких ставках или длинном горизонте малый DF может отображаться как ноль на 18 знаках; для машинной оценки используйте рассчитанный PV или расширьте версию контракта.

Порядок дат, число платежей ≤1200, совпадение results с payment_types, равенство итогов сумме строк, непрерывность долга и полное погашение — семантические проверки. Они не заменяются одной JSON Schema. Неизвестные поля отклоняются. Расчёт возвращает ошибку при некорректных параметрах, а не успешный ответ с частичными числами. В CLI это ненулевой код выхода и сообщение ERROR; формат транспортной ошибки API согласуется при добавлении API-адаптера.

Подключённый валидатор ответа должен зарегистрировать запрос по `$id` `urn:factor-analysis:cashflows:request:1.0`. Автотесты показывают это через `referencing.Registry` и включают FormatChecker для календарных дат.
