# Генератор портфеля, денежные потоки и сценарная оценка

## Запуск

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
.\START_APP.cmd
```

Основной поддерживаемый вариант приложения — Windows и многоконфигурационная сборка build/Release. Наличие dashboard.exe рядом с portfolio_app.exe обязательно. Полная переносимость на другие платформы и произвольные каталоги сборки не заявлена.

## CLI

```powershell
.\build\Release\portfolio.exe --profile short --out run-1
.\build\Release\portfolio.exe --config run-1/config.ini --out replay
```

Каталог вывода должен отсутствовать или быть пустым. Существующие результаты не перезаписываются. Профили default, short, long, floating доступны в CLI; profiles/*.ini содержат примеры. В браузере встроенные профили и пользовательские настройки доступны через форму. Пользовательские профили сохраняются только в этом браузере (localStorage); перенос — через INI.

## Параметры INI

| Ключ | Смысл и единицы |
|---|---|
| version | Версия конфигурации: 1.0.0 |
| count | Количество сделок, не общий денежный объём; CLI 1..1000000, интерактивный режим до 100000 |
| seed | Seed исходного портфеля, 0..4294967295 |
| min_amount/max_amount | Диапазон суммы в копейках |
| min_term/max_term | Сроки в месяцах |
| ann/simple/rgm | Доли по количеству сделок в сотых процента; сумма 10000 |
| floating | Доля плавающих сделок в сотых процента |
| min_rate/max_rate | Фиксированные ставки в базисных пунктах; 1200 = 12% |
| min_spread/max_spread | Надбавки к TEST_INDEX в базисных пунктах |
| valuation_date | Дата оценки и условной выдачи исходных сделок, YYYY-MM-DD; по умолчанию 2022-08-31 |
| discount_rate | Единая ставка дисконтирования, б.п.; по умолчанию 750 = 7,5% |
| index_rate | Плоский TEST_INDEX, б.п.; по умолчанию 750 |
| scenario_date | Дата сценария, строго позже valuation_date; по умолчанию 2022-11-30 |
| scenario_discount | Ставка дисконтирования сценария, б.п.; по умолчанию 850 |
| new_count | Число добавляемых сделок; по умолчанию 100, 0 отключает добавление |
| new_seed | Seed добавляемых сделок; по умолчанию 43 |

Неуказанные параметры получают значения по умолчанию. Если меняете valuation_date, проверьте scenario_date: фиксированное значение по умолчанию может оказаться раньше даты оценки. Версия 1.0.0 пока не отделяет версию генератора от версии модели оценки.

## Денежные потоки

Первый платёж — через месяц после даты оценки. Погашение — через срок сделки в месяцах. Календарь последующих дат привязан ко дню первого платежа; короткий месяц обрезает день, дата погашения включается ровно один раз. Это важно, например, для выдачи 31 августа: первый платёж 30 сентября, следующие привязаны к 30-му числу.

ACT/365F: фактические дни периода делятся на 365. ANN — аннуитет с коэффициентами на фактических датах; SIMPLE — проценты по периодам и всё тело в конце; RGM — равномерное погашение тела с корректировкой последнего платежа. Деньги графика хранятся в целых копейках; проценты округляются HALF_UP. Отрицательная амортизация ANN отклоняется.

Для плавающей сделки используется постоянная ставка TEST_INDEX + надбавка. Кривой индекса, прогнозов и дат пересмотра нет: это упрощение, а не полноценная модель плавающей ставки.

## PV и точность

Дисконтирование PERIOD_SIMPLE_CHAIN: DF последовательно делится на 1 + ставка * дни / 365. Это не XNPV и не эффективное годовое дисконтирование.

Процентные суммы вычисляются с целочисленными промежуточными операциями. Для аннуитетных коэффициентов и дисконтирования применяется самописная double-double арифметика; наружу DF и PV возвращаются как double. Это не десятичная арифметика с 40 значащими цифрами, предусмотренная исходным предложением docs/cpp-module.md. Совпадение с эталонным примером не доказывает точность на всех допустимых входах.

cashflow_reference сверяет все 334 строки каждого графика ANN/SIMPLE/RGM с CSV первого спринта: деньги точно, DF с допуском 1e-12, PV с допуском 1e-7 RUB. Проверяются также итоговые суммы и выбранные граничные случаи. Полное покрытие переполнений и независимый аудит численной реализации ещё нужны.

## Расчётный факторный анализ

Метрика: PV оставшихся будущих платежей плюс уже полученные к дате оценки платежи, без процентов на полученные деньги. Исходный портфель выдан на valuation_date; новые сделки выданы на scenario_date и генерируются теми же распределениями с new_seed.

Считаются восемь комбинаций факторов «время / ставка / состав». Основные вклады определяются относительно исходного состояния; парные и тройное взаимодействия — включением-исключением. Алгебраическая сумма семи вкладов равна изменению метрики с учётом численного округления. Округлённые отдельно CSV-строки могут дать копеечное расхождение.

Это не Shapley-разложение: взаимодействия показаны отдельно. Комбинации с будущими новыми сделками на более раннюю дату являются условными контрфактическими оценками. Изменение состава сейчас означает только добавление сделок; выбытий и продаж нет.

Рост метрики от добавленных кредитов не является прибылью: исходящий денежный поток выдачи новых кредитов и стоимость фондирования не вычитаются. Результат нельзя называть полным NPV или Economic Capital. PD/LGD/EAD, дефолты, рыночные кривые, комиссии и досрочные погашения не моделируются.

Оценка и факторный анализ работают строго: ошибка сделки прерывает весь расчёт с ID, причиной и указанием исходного или нового набора. Оба расчёта выполняются до создания выходного каталога и записи файлов отчёта. Ошибка расчёта не оставляет частичные выгрузки. Это не транзакционная защита от ошибок диска во время последующей записи файлов.

## Выходные файлы

- portfolio.csv — параметры всех исходных сделок; результат генерации защищён golden-тестом seed 42.
- config.ini — полный конфиг для воспроизведения.
- summary.txt — заданные и фактические распределения исходного портфеля.
- report.html — параметры, сделки, PV, месячные потоки и расчётные факторы.
- portfolio_cashflows.csv — агрегированные месячные потоки (денежные суммы в копейках, PV в рублях).
- factor_analysis.csv — вклады факторов и итоговые значения в рублях.

В HTML показаны первые 24 месяца, полный месячный горизонт доступен в CSV. Отдельные параметры новых сделок и их графики пока не экспортируются.

## Проверки и ограничения

ctest включает ядро генератора, golden seed 42, согласованность профилей, ошибки конфигурации, CF fixture, эталоны платежей, оценку и факторы. HTTP-проверка: python tests/app_smoke.py. Браузерная проверка: python tests/browser_e2e.py; она не является частью ctest и не гарантирует покрытие новых полей и отчётов.

Форма и генератор используют равномерные тестовые распределения. Портфель изначально состоит из одновременно выданных сделок, а не смеси разной зрелости. HTML содержит все исходные сделки и может быть тяжёлым; расчёт большого портфеля требует отдельного нагрузочного тестирования. Текущие максимумы формы не являются подтверждённой гарантией производительности.

Отдельная вкладка «Факторный анализ · ДЕМО» остаётся заранее заданным примером, не результатом расчёта. Импортированные CF валидируются и показываются отдельно; расчётный анализ генератора к ним не применяется.
